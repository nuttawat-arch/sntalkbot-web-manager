แนวทางการทำงาน

Web Manager เป็น UI สำหรับ SNTalkBot + TTUHelper ไม่มีช่อง shell อิสระ งานสิทธิ์สูงผ่าน privileged bridge ที่อนุญาตเฉพาะ action ที่กำหนดไว้

บริการ Web Guardian

Reverse Proxy ภายนอกชี้มาที่ 127.0.0.1:28765 ซึ่งเป็น Guardian 1.0.0 ที่ติดตั้งครั้งเดียวและคงอยู่ระหว่างการอัปเดต ส่วน FastAPI Web Manager ทำงานภายในที่ 127.0.0.1:28766 เมื่อ backend restart Guardian จะแสดงหน้า maintenance/สถานะชั่วคราวแทน raw 502 และหน้า Job ของ self-update จะรอตรวจ process generation ใหม่ให้อัตโนมัติ

สิทธิ์ผู้ใช้

ผู้เปิดเว็บครั้งแรกสร้าง Super Admin คนแรก จากนั้น Super Admin เท่านั้นสร้างบัญชีเพิ่ม ผู้ใช้ทั่วไปเห็นและจัดการเฉพาะ instance ที่ตนเองสร้าง ส่วน System, Users และ Migration เป็นเมนู Super Admin

การยืนยัน TeamTalk Administrator

ตอนสร้าง instance ผู้ใช้ต้องกรอก TeamTalk username ของตนเองและออนไลน์อยู่บน TeamTalk server นั้น เว็บจะเริ่มบอตชั่วคราวและตรวจรายชื่อ Administrator จากสถานะจริง บัญชี TeamTalk ของบอตเองถูกตัดออกทั้งด้วย User ID และ username จึงใช้บอตหรือ session อื่นของบัญชีบอตเป็นหลักฐานแทนเจ้าของไม่ได้

Realtime API และความหมายของตัวเลข

TTUHelper จัดพอร์ต loopback ช่วง 20000–27999 ให้แต่ละ instance แบบไม่ซ้ำและเก็บ token ใน instance.conf SNTalkBot API เป็น read-only และรับเฉพาะ Bearer token จาก localhost เว็บใช้ API นี้ก่อน แล้วค่อย fallback ไป runtime_status.json เฉพาะเมื่อ container ยังรันอยู่

SNTalkBot 5.1.2+ รายงาน ผู้ใช้ในห้องปัจจุบัน แยกจาก ผู้ใช้ทั้งเซิร์ฟเวอร์ และแสดงรายชื่อคนในห้องพร้อม User ID/username/nickname/status/client, Administrator, Voice/Media/Video/Desktop โดยไม่รวมบัญชี TeamTalk ของบอตเอง ถ้า container หยุด เว็บจะซ่อน snapshot เก่าและแสดงว่าไม่มีข้อมูลสด

จำนวนคำสั่ง

SNTalkBot Full มี 124 canonical commands ส่วน TTUHelper มี 22 commands ในรุ่นปัจจุบัน การเพิ่ม . <หมายเลขคิว> และ , <หมายเลขคิว> ไม่ทำให้ SNTalkBot เป็น 126 เพราะเป็น syntax เพิ่มเติมของคำสั่ง . และ , ที่มีอยู่แล้ว

TTUHelper และ action จริงบนหน้าเว็บ

หน้าเว็บไม่ได้เรียก CLI แบบ interactive ทุกคำสั่งตรง ๆ เพราะบางงานต้องตรวจ ownership/CSRF และทำแบบ non-interactive ตารางนี้ระบุว่าอะไรเรียก TTUHelper จริงและอะไรเป็นความสามารถเทียบเท่าที่เว็บทำเองอย่างปลอดภัย

new
Web-native equivalent: ฟอร์มสร้าง instance อ่าน template จาก Docker image, เขียน config แบบ non-interactive แล้วเรียก run ชั่วคราวเพื่อยืนยัน TeamTalk Admin
run / stop / restart
เรียก TTUHelper จริง ผ่าน privileged bridge หลังตรวจสิทธิ์เจ้าของ instance
delete
เรียก TTUHelper จริง พร้อม --yes เฉพาะหลังหน้าเว็บตรวจ exact-name confirmation; TTUHelper backup ก่อนลบ
logs
Web-native: อ่าน docker logs ผ่าน root bridge หลังตรวจ TTUHelper ownership labels ไม่เปิด log ของ container อื่นชื่อชน
ls / ps
Web-native: Dashboard อ่าน instance root + Docker inspect ที่ผ่าน ownership guard จึงไม่ต้อง parse output CLI
start-all / stop-all / pull / update / doctor
เรียก TTUHelper จริง จากหน้า System
migrate-ttmediabot
Privileged migration workflow: ใช้ migrator ที่ติดตั้งกับ TTUHelper/template จาก Docker image และกำหนด ownership ใน Web Manager หลังนำเข้า
cks / cks-all / cks-check
เรียก TTUHelper จริง โดยไฟล์อัปโหลดถูกจำกัดให้อยู่ใน Web Manager data directory และ Manager-only instance ถูกปฏิเสธตาม role
limit
Web-native: ตรวจรูปแบบ CPU/RAM แล้วเขียน limits.conf ใน instance data; TTUHelper ใช้ไฟล์นี้เมื่อสร้าง/recreate container
edit
Web-native: dynamic editor แก้ config.ini ทุก section/key พร้อม mask secret และล็อก TeamTalk identity ของ tenant
path
Web-native: แสดง instance/data path จาก production root ที่ตรวจแล้ว
version
หน้า System อ่าน ttuhelper version และแสดงเทียบรุ่น official
help
คู่มือเว็บนี้อธิบายความสามารถทั้ง 22 คำสั่งและระบุวิธี implementation ที่ใช้จริง

Self-update

ปุ่ม “อัปเดต Web Manager” clone รุ่นใหม่ลง staging, สำรอง source เดิม, ติดตั้งรุ่นใหม่ แล้ว restart เฉพาะ FastAPI backend แบบ delayed หลัง Job ตอบ success แล้ว Guardian ยังคงรับคำขอบน 28765 ระหว่าง backend 28766 เริ่มใหม่ หาก installer ล้ม ระบบ rollback source เดิมและคืน process เดิม

CloudPanel

สร้าง Reverse Proxy Site ให้โดเมน HTTPS proxy ไป http://127.0.0.1:28765 ซึ่งเป็น Guardian ไม่ต้อง proxy ไป 28766 และไม่ต้องเปิดพอร์ต 28765/28766 สู่สาธารณะโดยตรง

ความปลอดภัย

Web Manager service และ Guardian ใช้ system user sntalkweb ไม่ใช่ root ตลอดเวลา, มี CSRF, session ที่จำการเข้าสู่ระบบระยะยาว, login throttling, secret config masking, Docker ownership labels และไม่มี arbitrary command runner
