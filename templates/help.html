แนวทางการทำงาน

Web Manager เป็น UI สำหรับ SNTalkBot + TTUHelper ไม่มีช่อง shell อิสระ งานสิทธิ์สูงผ่าน privileged bridge ที่อนุญาตเฉพาะ action ที่กำหนดไว้

สิทธิ์ผู้ใช้

ผู้เปิดเว็บครั้งแรกสร้าง Super Admin คนแรก จากนั้น Super Admin เท่านั้นสร้างบัญชีเพิ่ม ผู้ใช้ทั่วไปเห็นและจัดการเฉพาะ instance ที่ตนเองสร้าง ส่วน System, Users และ Migration เป็นเมนู Super Admin

การยืนยัน TeamTalk Administrator

ตอนสร้าง instance ผู้ใช้ต้องกรอก TeamTalk username ของตนเองและออนไลน์อยู่บน TeamTalk server นั้น เว็บจะเริ่มบอตชั่วคราวและตรวจรายชื่อ Administrator จากสถานะจริง บัญชี TeamTalk ของบอตเองถูกตัดออกจากรายการนี้ จึงใช้บอตเป็นหลักฐานแทนเจ้าของไม่ได้

Realtime API

TTUHelper จัดพอร์ต loopback ช่วง 20000–29999 ให้แต่ละ instance แบบไม่ซ้ำและเก็บ token ใน instance.conf SNTalkBot API เป็น read-only และรับเฉพาะ Bearer token จาก localhost เว็บใช้ API นี้ก่อน แล้วค่อย fallback ไป runtime_status.json

CloudPanel

สร้าง Reverse Proxy Site ให้โดเมน HTTPS proxy ไป http://127.0.0.1:28765 ไม่ต้องสร้าง PHP site และไม่ต้องเปิดพอร์ต 28765 สู่สาธารณะ

ความปลอดภัย

Web Manager service ใช้ system user sntalkweb ไม่ใช่ root ตลอดเวลา, มี CSRF, session ที่จำการเข้าสู่ระบบระยะยาว, login throttling, secret config masking และไม่มี arbitrary command runner
